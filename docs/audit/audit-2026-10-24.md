# Auditoria do Mandrake v0, 2026-10-24

Escrita pelo Tiamati para quem vai manter o Mandrake. Cada linha diz o que foi feito e como foi
conferido. "Conferido" quer dizer rodado nesta máquina (macOS, Claude Code 2.1.310), não só testado
em unidade.

## Funciona, conferido no real

- `mandrake` sem argumentos: mostra o estado das duas camadas e o último bench.
- `mandrake setup --profile <f> --yes` e `./install.sh --profile <f>`: 0 erros; reinstala por cima de
  uma instalação existente; só diz que o proxy está no ar depois que a porta responde.
- `mandrake setup --cli`: 24 perguntas, uma por linha, respondidas por um terminal simulado
  (`tool/tests/e2e/pty-answer.py`) num HOME descartável: 0 erros, em 14 s.
- `mandrake doctor`: 11 checagens, todas ok.
- prompt-trim: a requisição que chega à API, auditada, tem no `system` o cabeçalho de billing, a
  linha de identidade e o core (4.251 caracteres); as 12 tools vão sem descrição (83 caracteres no
  total, contra 15.846 sem o Mandrake).
- Soul: `claude invoke tiamati` manda só o `TIAMATI.md` no `system`, sem o core
  (`core_only_plain = true` no perfil do Brenner).
- `mandrake bench`: A/B real com o login do usuário, 3 prompts × 2 = 6 requisições, 26 s:
  62.376 → 42.480 tokens (−31,9%). As requisições ficam para o `hex`.
- `mandrake bench --view`, `watch --snapshot`, `hex`, `link plan`, `proxy status`, `capture`.
- Proxy fora do ar: a sessão vai direto para a API e avisa (e2e `setup.sh`, checagem "proxy down").
- `cargo test` e `clippy -D warnings` limpos; `tool/tests/e2e/setup.sh`: 0 falhas.

## Defeitos encontrados nesta auditoria, já corrigidos

- `ANTHROPIC_BASE_URL` no `settings.json`: com o proxy fora, todas as sessões paravam. Agora o
  launcher do shell define a variável por sessão, só quando o proxy responde.
- O bench media requisições sintéticas, escritas para os testes, e não contava tokens sem
  `ANTHROPIC_API_KEY`. Agora o bench padrão é o A/B real; as fixtures ficaram em `--fixtures`.
- `install.sh` falhava ao reinstalar (`binary already exists`). Agora usa `--force`.
- `env.sh` sobrescrevia as variáveis vindas do ambiente.
- O setup dizia que o proxy estava no ar antes de a porta responder.
- A CLI estava em inglês e sem explicação. Agora está em português, cada comando diz o que faz e
  quanto custa, e `mandrake` sem argumentos explica as duas camadas.
- Fora do Mandrake, no tiamatiagent: `mem.sh whoami` não reconhecia nomes de sessão com o sufixo
  que o Claude Code acrescenta (`Tiamati-fizzy-ripple`), e por isso a busca na memória e o `/sleep`
  falhavam em sessões sem `TIAMATI_AGENT`. Corrigido em `agent/mcps/memory/mem.sh`, ainda não
  commitado: a branch aberta lá é de outra tarefa.

## Defeitos encontrados no teste de ponta a ponta, corrigidos no #6

Encontrados pelo Brenner (`docs/audit/e2e-2026-10-24.md`), conferidos no código e corrigidos com um
teste cada.

- Cópia que falhava no meio não era desfeita pelo rollback: o original ia para o backup antes de o
  passo entrar no journal. Agora o passo entra no journal como pendente antes de qualquer
  movimento, e o rollback desfaz também os pendentes.
- Duas aplicações no mesmo segundo dividiam o journal e a pasta de backup, e o setup gravava o
  backup do `settings.json` na mesma pasta do backup dos links. Agora cada execução reserva um
  nome próprio (`<stamp>-001`, `-002`…), que continua ordenado no tempo.
- O `doctor` acusava uma cópia correta, e cada setup fazia outro backup dela. Agora o plano compara
  a cópia com a origem, arquivo por arquivo e byte a byte, e não mexe quando são iguais.
- O `setup --cli` aplicava quando a entrada fechava, porque o fim da entrada valia como "sim".
  Agora a entrada fechada para o setup sem aplicar nada e sai com erro.

## O que ainda não está bom

- Só passam pelo proxy as sessões abertas por um shell com o bloco do Mandrake. O app desktop e as
  IDEs não passam pelo proxy, mas têm o prompt-trim, que é onde está quase toda a economia.
- O proxy sozinho economiza pouco (17 tokens por requisição). O valor dele é medir e auditar.
- O corte da identidade do CLI (`cut_identity`) fica desligado: numa sessão longa com assinatura,
  ele fez a requisição custar mais (269.338 → 291.637). A causa não foi investigada.
- O wizard em tela cheia (`mandrake setup` sem `--cli`) só foi aberto e fechado num pty, não
  percorrido até o fim. O `--cli` foi percorrido inteiro.
- Linux: nada foi compilado nem rodado lá. A unit do systemd só foi testada como texto gerado.
- O prompt-trim depende da API de módulos de plugin desta build do Claude Code (`hooks.json` com
  `modules`). Não foi conferido em outra versão.
- `tool/tests/e2e/reinstall-live.sh` (backup, Lixeira e reinstalação no real) não completou
  nenhuma rodada: a primeira travou no backup, a segunda foi interrompida. Esta sessão também
  não consegue ler a Lixeira do macOS (`Operation not permitted`).
- O `watch` só tem o lado esquerdo preenchido durante um A/B; no uso normal, só há o lado direito.

## Incidente desta sessão

A reinstalação de 2026-10-24 deixou o `~/.claude` sem os 23 links e o `settings.json` reduzido
entre 19:48 e 19:56. O que tirou os links não foi identificado. Nesse intervalo:

- uma sessão aberta como `/invoke quimera` nasceu sem o perfil da Quimera;
- o Claude Code mandou o cache de plugins para `plugin/.runtime/.trash`.

O `tool/relink.sh` refez os links a partir do mapa salvo e juntou aos destinos o que o Claude Code
tinha escrito nas pastas novas: 9 linhas de histórico, 3 transcripts e 33 checkpoints. As pastas
novas foram guardadas em `~/.claude-relink-20261024-200504`.
