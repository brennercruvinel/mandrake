## O que faz

- Reproduz a organização de `~/.claude` a partir de um perfil: links, cópias, plugins, launcher do shell e prompts de personas, chamadas de souls.
- O plugin prompt-trim remove partes do prompt padrão do Claude Code, vários lembretes e descrições de ferramentas; nas sessões comuns, acrescenta o core configurado.
- O proxy encaminha as requisições, remove campos configurados e tags de lembretes, mede tokens e registra eventos. Auditoria opcional guarda os corpos antes e depois.
- `watch`, `hex` e `bench` apresentam as medições e os cortes.

## Defeitos reproduzidos

### 1. Alta: erro durante uma cópia deixa o original fora do lugar e o rollback não restaura

Referências: `rust/layout/src/links.rs:161`, `:184`, `:187`.

Reprodução em pasta descartável:

1. Criar `.claude/rules/original.txt` com conteúdo conhecido.
2. Configurar `links.rules` com `action = "copy"` e um `target` inexistente.
3. Executar `mandrake link apply`, seguido de `mandrake link rollback`.

Observado: `apply` sai com código 1 depois de mover `rules` para backup. O registro dessa etapa só seria acrescentado ao journal depois da cópia, que falhou. `rollback` sai com código 0 e informa `rolled back 0 steps`, mas `original.txt` continua ausente do local original. O arquivo ainda existe no backup e exige recuperação manual.

### 2. Alta: duas aplicações no mesmo segundo sobrescrevem o journal

Referências: `rust/home/src/lib.rs:230`, `rust/layout/src/links.rs:153`, `:201`.

Reprodução:

1. Começar com uma pasta real `.claude/rules` contendo `original.txt`.
2. Aplicar um perfil que transforma `rules` em link para a pasta A.
3. No mesmo segundo, aplicar outro perfil que aponta para a pasta B.
4. Executar rollback duas vezes.

Observado: os dois `apply` retornam sucesso e o mesmo caminho de journal, identificado apenas até segundos. Há um journal, em vez de dois. O primeiro rollback retorna ao link A; o segundo falha com `no journal to roll back`. A pasta original permanece no backup, sem transação disponível para restaurá-la automaticamente.

### 3. Média: modo de cópia não fica estável e o doctor acusa divergência logo após setup

Referências: `rust/layout/src/links.rs:93`, `rust/cli/src/cmd.rs` na checagem dos links do doctor.

Reprodução: configurar `links.rules` como cópia de uma pasta existente; executar setup com esse perfil e depois `doctor`.

Observado: setup retorna 0 e copia corretamente. Sem mudar nenhum arquivo, `doctor` informa `FAIL links: 0 as the profile says, differ: rules`. O planejamento sempre escolhe `BackupCopy` quando o destino existe, inclusive se a cópia estiver idêntica. Portanto, setups repetidos refazem a cópia e criam backups desnecessários.

A falha adicional de proxy no doctor dos testes descartáveis é esperada: `MANDRAKE_HOME` impede carregar o serviço. A divergência de `rules` é a falha relevante.

### 4. Média: fechamento da entrada do assistente CLI confirma a instalação automaticamente

Referências: `rust/cli/src/ask.rs:19`, `:23`, `:225`.

Reprodução em ambiente descartável: executar `mandrake setup --cli` com a entrada padrão vazia e fechada, equivalente a `</dev/null`.

Observado: código de saída 0; perfil, settings e bloco do shell são gravados. EOF é tratado como aceitar todos os padrões, incluindo `aplicar [s]`. A interrupção da entrada deveria ser distinguida da confirmação explícita.
